Memory Phase Transition — All Recall Modes
Coverage at 60k compute steps · K = 50 to 100k · K ≥ 100k = full corpus in memory (no constraint)
Why This Metric

Memory K is the number of theorems the agent can hold simultaneously. Real automated theorem provers (ATPs) operate under strict memory budgets — GPU VRAM, proof state cache, retriever index size.

This experiment asks: given a fixed compute budget (60k proof attempts), how does memory capacity determine what fraction of a 99,412-theorem corpus you can prove? The coverage curve as a function of K is the "memory scaling law" for proof discovery.

Range: K = 50 to 100,000. The corpus has 99,412 theorems, so K ≥ 100k means all theorems fit in memory simultaneously — the memory constraint vanishes and no further phase transition occurs. The axis is capped here.

Legend

Color = exploration strategy

  • BFS (grey): Breadth-first — prove theorems in order of dependency depth
  • DFS (teal): Depth-first — push deep into dependency chains
  • Random (blue): Uniform random selection from currently-provable theorems
  • Greedy (red): At each step, pick the theorem that unlocks the most new theorems

Shape = recall mode

  • ○ none: stop — agent halts when it runs out of provable theorems
  • ■ matched: strategy-specific recall (BFS=oldest, DFS=newest, Random=random, Greedy=unblock)
  • ▲ hub_global: always recall the highest global out-degree theorem (oracle knowledge)
  • ▽ hub_local: always recall the highest local out-degree theorem (visible subgraph only)
Note

"matched" conceals 4 different policies. Greedy+matched = real planning (unblock). BFS+matched = FIFO. DFS+matched = LIFO. Random+matched = random recall.

Interpretation
  • K < 1,000 (tiny memory): All curves collapse near baseline (48.4%). Memory so small the agent thrashes — constantly evicting theorems it just recalled. No strategy can overcome this. Below a threshold, compute is wasted on recalls, not discoveries.
  • 1,000 < K < 30,000 (the interesting regime): Curves separate. Hub_global (▲) pulls ahead of matched (■) pulls ahead of none (○). Greedy (red) separates from others. Both recall strategy and exploration strategy matter. This is the realistic operating regime for bounded AI provers.
  • K > 30,000 (large memory): All curves converge toward 97.9% ceiling. Memory constraint lifted. Differences disappear. With enough memory, strategy is irrelevant — raw compute dominates. Axis is capped at K=100k (≥ corpus size); beyond that, memory is unconstrained by definition.
  • hub_global above hub_local: Gap quantifies the oracle information premium. A prover knowing the full library's dependency structure outperforms one limited to local exploration. Gap narrows as K grows.
  • Greedy consistently above others: Frontier-aware exploration has independent value from recall strategy. Even Greedy+none outperforms BFS+matched at mid-K.
Dilution & Accessibility Distribution
|Adjacent Possible| at moment of discovery · BFS steps to become provable
Why This Metric

"Dilution" measures selection difficulty — when a theorem becomes provable, how many other theorems are also provable at that moment?

A theorem with dilution=1 becomes uniquely provable in isolation. A theorem with dilution=18,000 competes with 18,000 alternatives the instant it unlocks.

High dilution means the proof space is saturated and selection is nearly random at the moment of discovery. This is the "needle in a haystack" problem for theorem proving.

Legend
  • Dilution = |Adjacent Possible| at the moment theorem T first becomes provable
  • Accessibility = how many BFS steps from root theorems until T's prerequisites are met
  • Mean dilution ≈ 9,789: a typical theorem is "diluted" among ~10,000 alternatives
  • Max dilution = 18,269: this theorem became provable exactly when the frontier peaked
Interpretation
Key Finding

Mathlib theorems are both structurally shallow (mean 1.84 BFS steps) AND buried in noise (mean dilution 9,789). The difficulty is not logical depth — it's selective attention.

  • Right-skewed dilution (mean 9,789, max 18,269): Most theorems enter a crowded frontier. Mathematical theory-building does not consist of obvious "next steps" — the frontier is always wide and alternatives abundant.
  • Shallow accessibility (mean 1.84 BFS steps): Despite dilution, most theorems are structurally close to the roots. The Mathlib DAG is wide, not deep. Difficulty is navigating a wide but shallow possibility space.
  • These two facts together: Reframes ATP from a search-depth problem to a retrieval/selection problem. A good prover needs selective attention, not deep reasoning.
  • If dilution were low (near 1): Proof discovery would be nearly deterministic. No selection strategy would matter. The finding that dilution ≈ 10k is precisely why strategy matters at all.
Recall Gain — Marginal Coverage Contribution of Memory Management
Coverage(with recall) − Coverage(no recall) · same strategy, same K, same budget
Why This Metric

Raw coverage tells you total success. Coverage gain isolates the marginal contribution of the recall mechanism — holding exploration strategy constant.

If recall gain > 0, recalling evicted theorems into memory helps. If recall gain = 0, memory was never a bottleneck. This is the ablation study for memory management.

Legend

Coverage gain = coverage(with recall) − coverage(no recall), at K for same budget

  • BFS (grey) — 3 series: matched (■), hub_global (▲), hub_local (▽)
  • DFS (teal) — 3 series: matched (■), hub_global (▲), hub_local (▽)
  • Random (blue) — 3 series: matched (■), hub_global (▲), hub_local (▽)
  • Greedy (red) — 3 series: matched (■), hub_global (▲), hub_local (▽)
Interpretation
Key Finding

Peak gain at K ≈ 5,000–50,000. This is the "sweet spot" where memory is constrained but not catastrophically small. Below 1k, recall is pure overhead (thrashing). Above 100k, memory holds everything.

  • Greedy dominates (gain up to +18pp): Greedy+matched achieves the largest gains because greedy's "recall" strategy is locally optimal (unblock). Not just recall helping — it's the combination of smart exploration and smart retrieval.
  • hub_global > hub_local in most regimes: The oracle premium is real. Knowing the full graph's degree structure produces better recall decisions. Practical implication: approximate global library statistics could substitute for oracle knowledge.
  • hub_local is noisy: Local structural signals are unreliable for recall. The agent's partial exploration gives unstable estimates of theorem importance. Don't build retrievers relying solely on local connectivity.
  • Gain → 0 at large K: As K increases, recall is never triggered. All gain curves return to 0 at K ≥ 100k. This confirms the measurement is well-calibrated.
Recall Fraction — Compute Overhead Tax of Memory Management
Recalls / Total Steps at 60k budget · fraction of compute spent managing memory vs discovering
Why This Metric

Recall fraction = fraction of compute budget spent on recalls rather than discoveries. It's the "overhead tax" of memory management.

If recall fraction = 0.9, the agent spends 90% of its 60k budget just shuffling theorems in and out of memory, leaving only 10% for actual proof search. This metric diagnoses whether a recall strategy is efficient or wasteful.

Legend

Recall fraction = recalls / (discoveries + recalls), at 60k budget

  • Near 1.0 = memory too small, agent is thrashing
  • Near 0.0 = memory large enough, recalls rarely needed
  • Crossover at ~50%: roughly equal time exploring and recalling
Interpretation
Key Finding

Crossover at K ≈ 30,000–50,000 marks the "working memory threshold" for the Mathlib theorem graph. Below: memory limited, recalls dominate. Above: memory sufficient, recalls nearly absent.

  • Small K (< 1,000): recall fraction 80–99%: Nearly all compute spent on recalls. Only 1–20% of steps are actual discoveries. Below K ≈ 1,000, recall strategies provide marginal benefit because there's barely any discovery happening.
  • DFS matched drops to near-0 much earlier (K ≈ 2,000): DFS+matched = LIFO recall. Since DFS explores deep chains, recently evicted theorems are often not useful. DFS effectively has very low recall utility.
  • hub_local has higher recall fraction than hub_global at same K: Local hub selection wastes more steps on unproductive recalls (unstable priorities). Explains why hub_local coverage gain is noisy.
  • Uniformly high recall fraction would mean: Every memory size is constrained and recall mode selection matters uniformly. The existence of a crossover confirms a natural "capacity threshold."
Cross-Recall Experiment — Recall Strategy Decoupled from Exploration
Coverage at K=10,000, @60k budget · Each cell = independent run · All strategy × recall combinations
Why This Metric

Previous experiments coupled recall strategy to exploration strategy (BFS always used FIFO recall, Greedy always used unblock). This obscured the real question: does the "unblock" recall strategy help BFS too?

This 4×6 grid runs every combination independently, breaking the coupling. It's the critical experiment for isolating the contribution of recall strategy.

Legend

Rows: exploration strategy (how the agent chooses what to prove next)

Columns: recall strategy (what to do when memory is full)

  • none: No recall — pure exploration baseline.
  • FIFO: Recall the oldest theorem ever known. "Remember ancient results."
  • LIFO: Recall the most recently evicted theorem. "Remember recent results."
  • random: Recall a uniformly random evicted theorem. Unstructured baseline.
  • ⭐ unblock: Recall the theorem that would immediately unblock the most adjacent-possible theorems. Locally optimal recall. The "smart librarian" strategy.
  • hub_local: Recall the theorem with the most successors visible in the agent's discovered subgraph. Structural recall, no oracle.
Baseline

48.4% = what random root selection achieves with no effort. Cell value = coverage fraction at K=10,000, 60k compute budget.

Interpretation
Key Finding

Unblock column is nearly uniform across rows (64.5–64.7%). All four exploration strategies achieve nearly identical coverage with unblock recall. Recall strategy dominates over exploration strategy.

  • None column uniform (49.7%): Without recall, all strategies equivalent at K=10k. Memory, not exploration, is the binding constraint below crossover.
  • FIFO helps modestly (+1–2pp): Recalling old theorems occasionally opens new chains. Not efficient but not harmful.
  • LIFO is nearly useless: The theorem just left — it probably didn't unlock much when evicted.
  • Random recall moderate (+4–5pp): Better than LIFO, worse than unblock. A random "read but forgotten" theorem has some chance of being useful.
  • hub_local inconsistent (+5pp avg): Local structural signals are noisy. Better than random, worse than unblock.
  • Prescription for neural provers: Invest in retrieval quality (unblock-like recall), not just better search strategies. A BFS prover with smart retrieval outperforms a Greedy prover with dumb retrieval.
Cost-Constrained Discovery — Optimal Memory Window
cost_per_step = max(1, K) · TIME_BUDGET = 60M comp-equiv · K=1k → 60k steps (calibration)
Cost Model (fix.md)

Tactic application is not free. At memory K, each discovery attempt costs max(1, K) compilation-equivalents — the kernel checks the term against up to K premises.

With TIME_BUDGET = 60 million, larger K means fewer steps:

  • K=100 → 600k steps (10× more than base)
  • K=1,000 → 60k steps (calibration point)
  • K=10,000 → 6k steps (10× fewer)
  • K=30,000 → 2k steps (30× fewer)
Strategies

Existing (hollow diamonds in EFG):

  • BFS · DFS · Random · Greedy — same algorithms, cost-scaled budget

New cost-aware strategies:

  • min_cost: pick theorem with fewest total prerequisites (cheapest to verify)
  • efficient: maximise (theorems unlocked) / max(1, prereqs) — gain per unit cost
Key Prediction

Coverage vs K becomes non-monotonic: peak at K where retrieval benefit balances step-cost penalty. Too small = memory bottleneck. Too large = step bottleneck.

Results
Non-Monotonic Peak Confirmed

Coverage peaks near K ≈ 20,000 (~51.4%) for all strategies, then falls as the step budget collapses. The optimal memory window is real.

  • Orange dashed (right axis): Steps = 60M / K — collapses 1,200× from K=50 to K=∞.
  • K < 1k: Memory bottleneck dominates. All strategies near baseline despite abundant steps.
  • K ≈ 20k: Coverage peaks. Memory sufficient to hold most of the active frontier; steps still adequate.
  • K > 20k: Step starvation — only 2k steps at K=30k, 60 steps at K=∞. Coverage falls below baseline.
  • hub_local recall adds +1–2pp at small-to-mid K where steps allow it. Advantage disappears at large K.
  • min_cost & efficient match or slightly exceed existing strategies — the advantage of efficiency is modest at these K values.
